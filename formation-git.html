Git, GitHub et Jules, du premier commit à l'agent IA

Ce que sont un repo, un commit, une branche et une pull request, les commandes à connaître par cœur, et comment piloter Jules depuis ton terminal. Chaque bloc de code se copie en un clic.

13 modules~1 h 30Compte GitHub : Raphgtnr
01

Les concepts

Git est un logiciel installé sur ton Mac qui enregistre l'historique de tes fichiers. GitHub est un site web qui héberge des copies de ces historiques en ligne, pour les sauvegarder, les partager et collaborer. Git fonctionne sans GitHub ; GitHub ne sert à rien sans Git.

Analogie qualité

Un commit, c'est une révision indicée d'un plan : on sait qui a modifié quoi, quand et pourquoi, et on peut revenir à l'indice B à tout moment. Git fait ça pour un dossier entier, automatiquement.

Les 4 zones où vivent tes fichiers

Vocabulaire

Repository (repo)
Un dossier de projet suivi par Git, avec tout son historique. Ex. : Raphgtnr/INJECTIONPLASTIC.
Commit
Une photo de l'état du projet, avec un message. Identifié par un hash (a3f9c21).
Branch
Une ligne de travail parallèle. main est la branche principale.
Remote / origin
La copie distante du repo (sur GitHub). origin est son surnom par défaut.
Clone
Télécharger un repo GitHub sur ton Mac, historique compris.
Push / Pull
Envoyer tes commits vers GitHub / récupérer ceux de GitHub.
Pull request (PR)
Une demande de fusion d'une branche dans main, avec relecture. C'est ce que Jules t'a proposé ce soir.
Merge
Fusionner une branche dans une autre.
Fork
Ta propre copie, sur GitHub, du repo de quelqu'un d'autre.
Diff
Les lignes ajoutées (+) et supprimées (−) entre deux versions.
02

Installer et configurer

À faire une seule fois sur ton Mac.

  1. Vérifier Git (macOS propose d'installer les outils développeur s'il manque).
    Terminal
    git --version
  2. Te présenter à Git : ce nom et cet e-mail signent chaque commit.
    Terminal
    git config --global user.name "Raphaël Gouttenoire"
git config --global user.email "raphgouttenoire01@gmail.com"
git config --global init.defaultBranch main
  3. Installer le CLI GitHub (gh) : il gère la connexion et crée des repos sans passer par le site.
    Terminal
    brew install gh
gh auth login
    Réponds : GitHub.com → HTTPS → Yes (authentifier Git) → Login with a web browser, puis colle le code affiché.
  4. Activer les commentaires dans zsh (évite l'erreur de ce soir avec les #).
    Terminal
    echo 'setopt interactivecomments' >> ~/.zshrc
source ~/.zshrc
Vérification

gh auth status doit afficher Logged in to github.com account Raphgtnr.

03

Créer un repo

Deux cas de figure selon où se trouve ton projet au départ.

Cas A : le projet existe déjà sur ton Mac

Terminal
# 1. Aller dans le dossier du projet
cd ~/Documents/mon-projet

# 2. Transformer le dossier en repo Git
git init

# 3. Premier commit
git add .
git commit -m "Premier commit"

# 4. Créer le repo sur GitHub et tout envoyer en une commande
gh repo create mon-projet --private --source=. --remote=origin --push

Cas B : le repo existe sur GitHub, tu veux le récupérer

Terminal
cd ~/Documents
gh repo clone Raphgtnr/INJECTIONPLASTIC
cd INJECTIONPLASTIC

Équivalent sans gh : git clone https://github.com/Raphgtnr/INJECTIONPLASTIC.git.

Cas C : partir de zéro sur GitHub

Terminal
gh repo create nouveau-projet --private --add-readme --clone
cd nouveau-projet
Privé par défaut

Tout repo qui touche à SFCME, Schneider ou à des données personnelles reste en --private. Un repo public est visible par tout Internet et indexé par les moteurs de recherche.

04

Le cycle quotidien

90 % de ton usage de Git tient dans ces six commandes, toujours dans cet ordre.

La boucle
# 0. En début de session : récupérer les changements (les tiens d'un autre poste, ceux de Jules…)
git pull

# 1. Voir ce qui a changé
git status

# 2. Préparer les fichiers (un fichier, ou tout avec .)
git add script.py
git add .

# 3. Enregistrer avec un message clair
git commit -m "Ajoute le calcul du RPN par poste"

# 4. Envoyer sur GitHub
git push

Lire l'historique

CommandeCe que tu vois
git log --onelineUn commit par ligne : hash + message
git log --oneline --graph --allL'arbre des branches
git diffLes modifications pas encore ajoutées (add)
git diff --stagedCe qui partira au prochain commit
git show a3f9c21Le détail d'un commit précis
Écrire un bon message de commit
  • Verbe à l'impératif, au présent : « Corrige », « Ajoute », « Supprime ».
  • Une seule intention par commit. Si ton message contient « et », fais deux commits.
  • À éviter : « modif », « update », « test ». Dans six mois tu ne sauras plus ce que c'était.
05

Branches et pull requests

Une branche te permet d'essayer quelque chose sans toucher à la version qui marche. Quand c'est prêt, tu ouvres une pull request pour fusionner dans main.

Le flux complet

Terminal
# 1. Créer une branche et s'y placer
git switch -c feature/export-excel

# 2. Travailler, puis commiter normalement
git add .
git commit -m "Ajoute l'export Excel des défauts"

# 3. Pousser la branche (-u la relie à GitHub la première fois)
git push -u origin feature/export-excel

# 4. Ouvrir la pull request
gh pr create --fill

# 5. Fusionner et supprimer la branche
gh pr merge --squash --delete-branch

# 6. Revenir sur main à jour
git switch main
git pull
CommandeRôle
git branchListe les branches locales (* = branche active)
git switch mainChanger de branche
git branch -d nomSupprimer une branche déjà fusionnée
gh pr listVoir les PR ouvertes (dont celles de Jules)
gh pr checkout 12Récupérer la PR n°12 en local pour la tester
gh pr view --webOuvrir la PR dans le navigateur
Squash, merge ou rebase ?

Seul sur ton projet, prends squash : tous les commits de la branche deviennent un seul commit propre dans main.

06

.gitignore et secrets

Le fichier .gitignore, à la racine du repo, liste ce que Git doit ignorer. C'est la protection n°1 de tes clés API.

.gitignore (Python, à copier tel quel)
# Secrets
.env
*.key
credentials.json

# Python
__pycache__/
*.pyc
.venv/
venv/

# macOS
.DS_Store

# Données lourdes ou sensibles
data/
*.xlsx
*.csv

Ranger une clé API proprement

.env (jamais commité)
GEMINI_API_KEY=ta_cle_ici
script.py
import os
from dotenv import load_dotenv   # pip install python-dotenv

load_dotenv()
cle = os.getenv("GEMINI_API_KEY")
Clé poussée par erreur sur GitHub

Supprimer le fichier dans un nouveau commit ne suffit pas : la clé reste dans l'historique, et des robots scannent GitHub en permanence.

  • Révoque la clé immédiatement (AI Studio → API keys → supprimer) et crée-en une nouvelle.
  • Ensuite seulement, nettoie le repo.
Fichier déjà suivi

Ajouter un fichier au .gitignore n'a aucun effet s'il est déjà commité. Retire-le du suivi sans l'effacer du disque : git rm --cached .env, puis commit.

07

Annuler et réparer

Trouve ta situation dans le tableau. Les lignes rouges détruisent du travail non commité.

SituationCommandeRisque
J'ai cassé un fichier, je veux sa dernière version commitéegit restore fichier.pyPerd les modifs du fichier
J'ai fait git add sur un fichier par erreurgit restore --staged fichier.pyAucun
Faute dans le message du dernier commit (pas encore poussé)git commit --amend -m "Bon message"Aucun
Oublié un fichier dans le dernier commit (pas poussé)git add oubli.py puis git commit --amend --no-editAucun
Annuler le dernier commit en gardant les fichiers (pas poussé)git reset --soft HEAD~1Aucun
Annuler un commit déjà pousségit revert a3f9c21Aucun : crée un commit inverse
Mettre mes modifs de côté pour faire un pullgit stash … git stash popAucun
Tout jeter et revenir exactement à GitHubgit fetch puis git reset --hard origin/mainPerd tout le travail local
Règle d'or

Un commit déjà poussé ne se réécrit pas (amend, reset) : on le corrige avec revert ou un nouveau commit.

Filet de sécurité

git reflog liste tout ce que tu as fait, même les commits « perdus » après un reset. Tant que c'était commité, c'est récupérable.

08

Les conflits

Un conflit arrive quand deux versions modifient les mêmes lignes (toi et Jules, ou ton Mac et le site GitHub). Git ne choisit pas à ta place et marque le fichier :

fichier en conflit
<<<<<<< HEAD
seuil_rpn = 100      # ta version
=======
seuil_rpn = 125      # la version qui arrive
>>>>>>> origin/main
  1. git status liste les fichiers en conflit.
  2. Ouvre-les dans VS Code : il propose « Accept Current », « Accept Incoming » ou « Accept Both ». Supprime les marqueurs <<<, ===, >>>.
  3. Termine :
    Terminal
    git add fichier.py
git commit -m "Résout le conflit sur le seuil RPN"
git push
Prévenir plutôt que guérir

Fais git pull avant de commencer à travailler, et toujours avant de lancer une tâche Jules sur une branche que tu modifies toi-même.

Paniqué en plein merge ? git merge --abort remet tout comme avant.

    steps:

10

Jules depuis le terminal

Jules est un agent qui clone ton repo dans une machine cloud, code, teste, puis te rend une branche ou une pull request. Le CLI jules le pilote sans ouvrir le site.

Installation (une fois)

Terminal
sudo npm install -g @google/jules
jules login
jules remote list --repo

La dernière commande liste les repos autorisés. Pour en ajouter : GitHub → Settings → Applications → Google Labs Jules → Configure.

Le cycle Jules

Les commandes

CommandeRôle
julesInterface interactive (/new pour créer, /remote pour le tableau de bord)
jules remote list --repoRepos connectés
jules remote list --sessionTes tâches, leur ID et leur statut
jules remote new --repo X --session "…"Lancer une tâche
jules remote new --repo . --session "…"Même chose, repo déduit du dossier courant
jules remote new … --parallel 2Deux essais en parallèle sur la même tâche
jules remote pull --session 1485…Afficher le diff produit
jules helpToutes les options de ta version

Workflow complet sur un vrai projet

Terminal
# 1. Se placer dans le projet, à jour
cd ~/Documents/mon-projet
git pull

# 2. Confier la tâche
jules remote new --repo . --session "Ajoute des tests pytest pour toutes les fonctions de calcul.py. Ne modifie pas calcul.py."

# 3. Suivre
jules remote list --session

# 4. Approuver le plan sur jules.google.com, puis Publish PR

# 5. Relire et fusionner la PR depuis le terminal
gh pr list
gh pr diff 3
gh pr merge 3 --squash --delete-branch

# 6. Récupérer le résultat en local
git pull

Écrire une bonne tâche

Trop vagueExploitable
« Améliore le code »« Dans export.py, remplace les boucles par pandas pour accélérer l'export. Garde la même signature de fonction. »
« Corrige les bugs »« parse_datamatrix() plante si le code fait moins de 12 caractères. Renvoie None dans ce cas et ajoute un test. »
« Fais une app »« Crée un script CLI qui lit un CSV de défauts et génère un Pareto en PNG avec matplotlib. »
Formule

Fichier ciblé + ce qu'il faut faire + contrainte (« ne modifie pas… ») + preuve (« ajoute un test »).

Confidentialité

Les erreurs de ce soir

Les trois blocages rencontrés pendant l'installation, et pourquoi.

MessageCauseSolution
zsh: unknown file attribute: i
Invalid tag name "#"		zsh ne traite pas # comme un commentaire en mode interactif : il l'a passé à npm comme argument.Coller les commandes sans commentaire, ou setopt interactivecomments.
EACCES … mkdir /usr/local/lib/node_modules/@googlenpm veut écrire dans un dossier système qui ne t'appartient pas.sudo npm install -g @google/jules (mot de passe Mac, invisible à la frappe).
zsh: parse error near `\n'<ID> était un modèle à remplacer ; zsh lit < comme une redirection.Mettre le vrai numéro : --session 14852116661947841884.
zsh: command not found: julesL'installation avait échoué (lignes au-dessus).Corriger l'install, puis rouvrir le Terminal si besoin.
Réflexe

Dans un tutoriel, ce qui est entre chevrons (<ID>, <URL>, <nom>) est toujours à remplacer, chevrons compris. Et la vraie cause d'une erreur est généralement le premier message rouge, pas le dernier.

À vérifier
